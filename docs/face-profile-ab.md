# 페이스 프로필 v1.1 — 스펙 §6 A/B 실측 결과

**결론: 셀카 3장(정면+좌45+우45)이 1장보다 얼굴 정확도를 높인다는 증거가 없다.
따라서 "여러 각도라 더 정확하다"는 취지의 문구를 UI·스토어 어디에도 쓰지 않는다.**

측정일 2026-08-24 · 모델 nano_banana_pro(2K) · 컨셉 **342 내추럴 포트레이트**(라이브 카탈로그 실물)

## 프로토콜

프롬프트는 손으로 옮겨쓰지 않고 `api/generate.js` 의 `PHOTOREALISM` 을 소스에서 그대로 평가해 조립했다.
두 안의 차이는 **참조 장수와 faceClause 유무뿐**이고 본문·해상도·비율은 동일하다.

| | 참조 이미지 | faceClause |
|---|---|---|
| **A안** (페이스 프로필 OFF) | 정면 1장 | 없음 |
| **B안** (페이스 프로필 ON) | 정면 + 좌45 + 우45 | 있음 (`The final 3 reference images…`) |

각 5회, 총 10장.

## 판정 방법

자체 육안 판정은 편향되므로 **블라인드 판정 6회**를 붙였다. 판정자는 서로 독립이고 A/B 소속을 모른다.
원본과 후보를 나란히 붙인 이미지만 보고 "같은 사람인가" 1~5점.
메이크업·보정·머리길이·조명·배경·각도는 무시하도록 명시(프롬프트가 일부러 바꾸는 항목이므로).

- 라운드 1 (판정 3회): 기준 = 정면 원본 **1장**
- 라운드 2 (판정 3회): 기준 = 그 사람 **3각도 전체**. 후보 순서 재섞음.
  (라운드 1은 정면 1장을 정답으로 삼으므로 정면만 본 A안에 구조적으로 유리하다 → 기준을 공정하게 교정)

## 결과

| 판정 | A(1장) | B(3장) | B−A |
|---|---|---|---|
| R1-1 | 3.80 | 2.60 | −1.20 |
| R1-2 | 3.80 | 3.40 | −0.40 |
| R1-3 | 3.80 | 3.80 | 0.00 |
| R2-1 | 3.20 | 3.20 | 0.00 |
| R2-2 | 3.20 | 3.20 | 0.00 |
| R2-3 | 3.00 | 3.80 | +0.80 |
| **전체** | **3.47** | **3.33** | **−0.13** |

**판정자간 B−A 편차가 −1.20 ~ +0.80 (표준편차 0.65)로, 효과 크기(0.13)의 5배다.**
즉 A안이 낫다고도, B안이 낫다고도 말할 수 없다. 측정 가능한 차이가 없다.

## 부수 계측

- **배경 컬러캐스트**(상단 모서리 채도): A 평균 18.0 / B 평균 15.5 → 유의차 없음.
- **포즈 누출**: A는 5장 전부 정면. B는 5장 중 2장이 3/4 측면.
  `faceClause` 에 `never change the composition, framing, pose` 를 명시했는데도 좌45·우45 참조가
  구도로 새어나온 것으로 보인다. n=5라 확정은 아니지만, 사용자가 고른 컨셉의 프레이밍이
  깨지는 문제라 무시하면 안 된다.
  - 가설: 참조가 어깨·배경까지 포함한 프레임이라 구도 신호가 같이 따라간다.
  - 검증 방법: 저장 시점에 **얼굴만 타이트 크롭**해서 참조로 쓰고 재측정. (미실행)

## 이 측정의 한계 — 결론에 반드시 붙일 것

1. **좌45·우45 참조가 실제 촬영본이 아니다.** 정면 1장에서 AI로 파생시킨 이미지라 그 2장 자체에
   이미 인물 드리프트가 섞여 있다. 실제 제품에서는 사용자가 카메라로 각 각도를 직접 찍는다.
   → 이 설계는 B안에 불리하다. **"B안이 나쁘다"는 근거로는 약하고,
     "좋아진다고 주장할 수 없다"는 근거로는 충분하다.**
2. 인물 1명 · 컨셉 1종 · 각 5회. 일반화 불가.
3. 실제 촬영본 3각도를 가진 피험자로 재측정하면 결론이 달라질 수 있다.

## 제품 판단

- 페이스 프로필의 **검증된 가치는 편의성 하나**다 — "다음부터 사진을 안 올려도 된다".
  정확도 문구는 `src/FaceProfileSheet.jsx` 에서 제거했다.
- 스토어 설명문·프로모 문구에도 정확도 향상 취지를 쓰지 않는다.
- 포즈 누출은 출시 전 처리 필요(타이트 크롭 후 재측정 → 그래도 남으면 기능 보류 검토).
